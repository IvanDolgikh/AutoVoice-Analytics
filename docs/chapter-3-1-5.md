# 3.1.5 Описание программного кода

Программный комплекс «AutoVoice Analytics» реализован в виде одностраничного веб-приложения (SPA — Single Page Application) на основе фреймворка Vue 3 (версия 3.5) с использованием синтаксиса Composition API и `<script setup>`. Инструментом сборки служит Vite 8, обеспечивающий горячую замену модулей (HMR) в процессе разработки и оптимизированную компиляцию для продакшн-среды. Компонентная библиотека PrimeVue 4.5.5 с темой Aura используется для форм, выпадающих списков, кнопок и управляющих элементов. Диаграммы и графики реализованы через интеграцию Chart.js 4, доступную посредством компонента `primevue/chart`. Иконографика основана на наборе PrimeIcons. Управление глобальным состоянием приложения выполнено на основе авторского паттерна «реактивный синглтон» с применением примитивов `reactive` и `computed` из ядра Vue 3.

## Структура каталогов

Корневая директория проекта включает следующие ключевые каталоги и файлы:

- `src/main.js` — точка входа приложения: создание экземпляра Vue, подключение PrimeVue с темой Aura и конфигурацией тёмного режима (`darkModeSelector: '.dark-mode'`), монтирование в DOM-узел `#app`;
- `src/App.vue` — корневой компонент приложения, реализующий условный рендеринг: экран авторизации (`LoginView`) или рабочий интерфейс с шапкой (`AppHeader`), основной областью контента и виджетом поддержки (`SupportChat`); маршрутизация реализована через цепочку `v-if / v-else-if` с анимационными переходами (`<transition mode="out-in">`);
- `src/stores/appStore.js` (227 строк) — единственный модуль управления состоянием: реактивное хранилище, бизнес-логика ролевого разграничения доступа, вычисляемые данные по сотрудникам и критериям;
- `src/components/` — переиспользуемые компоненты: `AppHeader.vue` (270 строк), `LoginView.vue` (117 строк), `NotificationCenter.vue` (161 строка), `SupportChat.vue` (585 строк);
- `src/components/pages/` — компоненты страниц приложения (10 модулей общим объёмом около 6 500 строк);
- `src/style.css` — глобальные CSS-переменные, базовые стили, стили тёмного режима (`.dark-mode`), стили печати (`@media print`);
- `vite.config.js` — конфигурация Vite: плагины `@vitejs/plugin-vue` и `vite-plugin-vue-devtools`, псевдоним пути `@` для директории `src`;
- `package.json` — зависимости проекта и скрипты сборки.

## Хранилище состояния (appStore.js)

Модуль `src/stores/appStore.js` является центральным элементом архитектуры приложения и реализует паттерн «реактивный синглтон»: объект состояния `state` создаётся один раз на уровне модуля через `reactive()` и совместно используется всеми компонентами, вызывающими функцию `useAppStore()`.

**Статические данные** определены на уровне модуля и не изменяются в процессе работы приложения:

- `employees` — массив из 12 имён сотрудников трёх автосалонов;
- `employeeScores` — объект-словарь с балльными оценками каждого сотрудника (шкала 0–13);
- `empCriteria` — матрица выполнения восьми критериев скрипта продаж каждым сотрудником (экспортируется);
- `criteriaMax` — массив максимальных значений по каждому критерию `[1, 2, 1, 2, 2, 2, 1, 2]`, сумма равна 13;
- `criteria` — массив строковых наименований восьми критериев (экспортируется);
- `criteriaPct` — агрегированные процентные показатели выполнения критериев по всей команде (экспортируется);
- `allCalls` — массив из 12 объектов-звонков, генерируемый детерминированно из массива `employees` и псевдослучайных числовых последовательностей (`seed`, `salonSeed`, `dateSeed`);
- `navByRole` — объект, задающий навигационные меню для каждой роли: директору доступны 8 разделов, руководителю — 7, сотруднику — 5 (с заменой «Статистика» на «Мой дашборд» и добавлением раздела «Рейтинг» вместо недоступных модулей).

**Реактивное состояние** `state` содержит пять полей: `isLoggedIn` (признак авторизации), `currentRole` (текущая роль: `'director'`, `'manager'`, `'employee'`), `currentPage` (ключ активного раздела), `activeTags` (массив активных тегов-фильтров), `darkMode` (флаг тёмной темы).

**Экспортируемые вычисляемые свойства** (computed), создаваемые внутри `useAppStore()`:

- `navItems` — массив навигационных элементов текущей роли, реактивно пересчитывается при изменении `state.currentRole`;
- `calls` — отфильтрованный массив звонков: директор видит все 12 записей, руководитель — только 6 записей своей команды (`managerTeam`), сотрудник — только собственные звонки;
- `visibleEmployees` — список сотрудников, доступных текущей роли для просмотра;
- `myEmployeeName` — имя «текущего» сотрудника для роли `employee` (фиксировано как `'Новиков О.А.'`);
- `topEmployees` — пятёрка лучших сотрудников из числа `visibleEmployees`, отсортированная по убыванию балла;
- `allEmployeesRanked` — полный рейтинговый список всех 12 сотрудников с полями `rank`, `score`, `percent`, `isMe` (булев флаг, отмечающий позицию текущего пользователя);
- `criteriaData` — массив объектов `{ name, pct }` для отображения прогресс-баров критериев;
- `scoreReport` — построчная таблица оценок для экспорта отчётов;
- `roleLabel` — строковое отображение роли («Директор», «Руководитель», «Сотрудник»).

**Экспортируемые функции-помощники** модульного уровня:

- `getCriteriaPct(empName)` — возвращает массив из 8 процентных значений выполнения критериев конкретным сотрудником: `scores.map((s, i) => Math.round((s / criteriaMax[i]) * 100))`;
- `getTeamAvgCriteriaPct(teamNames?)` — вычисляет среднее выполнение каждого критерия по списку сотрудников; при отсутствии аргумента усредняет по всей команде.

**Методы управления состоянием**, возвращаемые из `useAppStore()`:

- `login(role)` — устанавливает `isLoggedIn = true`, `currentRole = role`, сбрасывает `currentPage` на `'stat'`;
- `logout()` — сбрасывает `isLoggedIn` и `currentRole` в исходные значения;
- `setPage(page)` — изменяет `currentPage`, что реактивно вызывает смену компонента страницы в `App.vue`;
- `addTag(tag)` / `removeTag(tag)` — управляют массивом активных тегов-фильтров;
- `toggleDarkMode()` — инвертирует `state.darkMode` и переключает CSS-класс `.dark-mode` на `document.documentElement`, что активирует тёмную тему PrimeVue.

## Компоненты страниц

Приложение содержит 10 компонентов-страниц, размещённых в директории `src/components/pages/`:

**StatPage.vue (889 строк)** — главная аналитическая страница, реализующая три независимых представления в зависимости от роли пользователя (условный рендеринг через `v-if / v-else-if / v-else` на основе `state.currentRole`). Представление директора включает: четыре KPI-карточки со спарклайнами на SVG, механизм сравнения периодов (анимированный блок с переходом `slide-down`), блок «Топ-5 / Зона внимания», тройной ряд диаграмм (горизонтальные гистограммы распределения баллов и воронки конверсии, кольцевую диаграмму типов звонков), линейный график динамики качества, радарную диаграмму критериев и тепловую карту активности по дням/часам. Представление руководителя содержит агрегированные KPI команды, горизонтальную гистограмму баллов по каждому сотруднику с цветовым кодированием (зелёный ≥ 70%, жёлтый 55–69%, красный < 55%), командный радар и детальную таблицу с процентным выполнением восьми критериев. Представление сотрудника отображает личные KPI-карточки (балл, звонки, место в рейтинге, процент выполнения), радарную диаграмму сравнения «мои критерии / среднее по команде», полный рейтинг команды с визуальным выделением собственной позиции и блок «Зоны роста» с рекомендациями по слабым критериям. Функция `sparkPath(vals, w, h)` вычисляет SVG-путь спарклайна по массиву значений с нормализацией в диапазон высоты.

**CallsPage.vue (745 строк)** — модуль работы со звонками. Содержит панель фильтров (диапазон дат через `DatePicker`, фильтр по салону и типу звонка через `Select`, восемь тегов критериев через кнопки-переключатели). Вычисляемое свойство `filteredCalls` применяет все активные фильтры к `calls.value` из хранилища. При выборе строки таблицы открывается боковая панель деталей звонка с тремя вкладками: транскрипт диалога с разметкой реплик по ролям, оценочный лист по восьми критериям скрипта, метаданные записи. Кастомный аудиоплеер реализован без использования HTML-элемента `<audio>`: воспроизведение симулируется таймером `setInterval`, обновляющим объект `playerTicks` (словарь «id звонка → секунды»); форма волны генерируется детерминированно функцией `waveformBars(id)` через суперпозицию двух синусоид: `6 + |sin((i + seed)·0.7)·24| + |sin((i + seed)·1.3)·10|`; маркеры нарушений скрипта отображаются на барах с индексами `[10, 11, 12, 24, 25]`; поддерживаются скорости воспроизведения 0.75×, 1×, 1.5×, 2×.

**ReportsPage.vue (721 строка)** — модуль аналитических отчётов. Реализует два типа отчётов: матрицу выполнения критериев (строки — сотрудники из `scoreReport`, столбцы — восемь критериев, цветовая кодировка ячеек) и воронку конверсии. Экспорт в CSV формирует строку через `\n`-разделитель и инициирует скачивание через динамически создаваемый тег `<a>` с атрибутом `download`. Экспорт в PDF использует вызов `window.print()` после программного отображения скрытого блока `.print-header`; разметка PDF управляется CSS-правилами в блоке `@media print` глобальной таблицы стилей.

**ScenariosPage.vue (923 строки)** — наибольший по объёму компонент, реализующий управление скриптами звонков: список сценариев с фильтрацией и поиском, редактор критериев с drag-and-drop сортировкой, управление весовыми коэффициентами, предпросмотр и активация/деактивация сценариев.

**GroupPage.vue (766 строк)** — модуль групповых проверок: настройка параметров пакетной оценки, запуск с прогресс-индикатором, сводная таблица результатов с фильтрацией и экспортом.

**GoalsPage.vue (269 строк)** — модуль целей и KPI. Состояние целей хранится в реактивном массиве `ref([])`. Для каждой цели вычисляется статус (`on_track` / `at_risk` / `achieved` / `overdue`) и количество дней до дедлайна через разность `Date.now()` и `new Date(goal.deadline)`. Форма добавления цели использует валидацию перед сохранением.

**CoachingPage.vue (310 строк)** — журнал coaching-сессий. Массив сессий хранится в `ref`, статус фильтрации управляется через `ref('all')`. Вычисляемое свойство `filteredSessions` возвращает отфильтрованный массив. Метод `completeSession(id)` находит сессию по id, устанавливает `status = 'done'`, добавляет поле `scoreAfter = scoreBefore + 7`.

**AchievementsPage.vue (298 строк)** — рейтинг и система достижений для роли «Сотрудник». Вкладка «Рейтинг» получает `allEmployeesRanked` из хранилища и отображает подиум топ-3 с медальными эмодзи и полную таблицу с прогресс-барами. Вкладка «Достижения» отображает каталог из шести типов значков с условиями получения.

**ProfilePage.vue (603 строки)** — личный кабинет пользователя. Профиль организован в четыре вкладки (Личные данные, Моя статистика, Настройки, Безопасность). Отображаемое имя вычисляется через `computed`: при пустых полях ФИО возвращается строка `'admin'`. Стаж рассчитывается формулой `Math.max(1, Math.round(ms / (1000·60·60·24·30.44)))`, где `ms` — разность текущей даты и `startDate`. Смена пароля сопровождается динамическим индикатором надёжности, оценивающим длину, наличие цифр и специальных символов.

**ChatPage.vue (795 строк)** — модуль ИИ-ассистента. Реализует интерфейс чата с имитацией ответов на основе анализа ключевых слов входящего сообщения и выбора из заранее подготовленных аналитических ответов. Поддерживает быстрые запросы (кнопки с предустановленными фразами), анимацию «печатает…» через `setTimeout` и автоскролл к последнему сообщению через `nextTick` + `scrollTop`.

## Вспомогательные компоненты

**AppHeader.vue (270 строк)** — шапка приложения, присутствующая во всех разделах. Навигационная панель формируется реактивно из `navItems` хранилища: при входе под разными ролями набор вкладок изменяется без перезагрузки. Активная вкладка определяется сравнением `state.currentPage === item.key`. Кнопка переключения темы вызывает `toggleDarkMode()` из хранилища. Щелчок по блоку пользователя вызывает `setPage('profile')`, кнопка выхода — `logout()` с отменой всплытия события через `@click.stop`.

**NotificationCenter.vue (161 строка)** — центр уведомлений. Хранит массив объектов-уведомлений в `ref`. Непрочитанные элементы выделяются на основе поля `read`. Реализовано закрытие панели по щелчку вне её области через обработчик `document.addEventListener('click', ...)`, регистрируемый в `onMounted` и удаляемый в `onUnmounted`. При открытии панели запускается таймер автоматического прочтения всех уведомлений через 2,5 секунды.

**SupportChat.vue (585 строк)** — виджет технической поддержки в правом нижнем углу. Реализует полноценный чат с имитацией ответов оператора, историей переписки, возможностью прикрепить файл и оценить качество обслуживания.

**LoginView.vue (117 строк)** — экран авторизации. Содержит поля `InputText` (логин), `Password` (пароль с маскировкой) и `Select` (выбор роли). По нажатию кнопки вызывается `login(selectedRole)` из хранилища.

## Навигация и маршрутизация

Маршрутизация реализована без использования Vue Router. В корневом компоненте `App.vue` цепочка из 10 директив `v-if / v-else-if` сопоставляет значение `state.currentPage` с соответствующим компонентом страницы. Переходы между страницами анимированы через `<transition name="page" mode="out-in">` с CSS-правилами: появление (`opacity: 0 → 1`, `translateY(6px → 0)`) и исчезновение (`opacity: 1 → 0`, `translateY(0 → -4px)`), длительность 180 мс. Атрибут `key` на каждом компоненте гарантирует пересоздание экземпляра при смене страницы.

## Ролевое разграничение доступа

Система разграничения доступа (RBAC) реализована на уровне хранилища без использования сторонних библиотек. Три роли (`director`, `manager`, `employee`) определяют три независимых набора: навигационных вкладок (`navByRole`), доступных звонков (`calls` computed), видимых сотрудников (`visibleEmployees` computed) и содержимого аналитического дашборда (ветви `v-if` в `StatPage.vue`). Расширение ролей не требует изменений в компонентах — достаточно добавить запись в объект `navByRole` хранилища.

## Тёмный режим

Тёмная тема реализована через CSS-переменные. В файле `style.css` определены два набора значений: базовый (`:root`) и переопределённый для класса `.dark-mode` на корневом элементе страницы. При вызове `toggleDarkMode()` класс добавляется или удаляется через `document.documentElement.classList.toggle()`. PrimeVue автоматически применяет тёмные токены темы Aura при совпадении с `darkModeSelector: '.dark-mode'`, указанным в конфигурации `main.js`. Таким образом, переключение темы затрагивает одновременно и пользовательские стили, и компоненты библиотеки.

## Итог по структуре кода

Программный комплекс AutoVoice Analytics насчитывает 17 исходных файлов общим объёмом около 7 750 строк кода. Код организован по принципу разделения ответственности: хранилище `appStore.js` содержит всю бизнес-логику и данные, компоненты-страницы отвечают исключительно за отображение и пользовательское взаимодействие, вспомогательные компоненты (`AppHeader`, `NotificationCenter`) обеспечивают переиспользуемую функциональность интерфейса. Применение реактивного паттерна синглтона вместо Vuex или Pinia исключает внешние зависимости для управления состоянием и обеспечивает прозрачный поток данных через механизм `computed`-свойств Vue 3.
